# 验收范围

- 事实：每项改动有依据；现有页面位置、主体、设备、权限、保存及生效边界正确。
- 结构：三个板块名称一致；目录归属正确；所有ID唯一；缺少某类图示时移除空目录项；未知锚点回退到有效页面。
- 导航：在1440与1920等实际评审视口检查，向下滚动长页后顶部三板块仍可点击；切换归顶，锚点不被顶栏遮住；无上一步/下一步及重复状态目录。
- 静态：按场景展开、状态覆盖完整、箭头动作与分支准确、正文可放大、长页无字段裁切、组内滚动不撑破整个页面。
- 交互：走完主路径及关键拒绝/恢复路径；选择与搜索不丢草稿，取消不回填，未保存内容不生效；跨页面与跨角色引用正确状态；固定画板不随演示操作变化。
- 编辑：运行本Skill的validate-editor.mjs；逐页检查普通文案、功能说明和实际存在的弹窗。跨形态共用文案编辑后同步；静态样例与演示数据仍独立。
- 导出：实际导出并在新上下文打开，检查静态画板/图示、编辑文案、必要配置与业务交互保留，无编辑工具、业务重置或重复初始化。
- 通用边界：页面通过元数据注册；不要用商品等特定ID驱动外壳。记录真实业务/设备验证范围，不以本机模板通过替代其他需求验收。

- 强制执行validate-review.mjs：功能结构与静态画板组件必须实际存在，不能以标题替代；检查交互视口不宽于当前容器。
- 在实际查询、账户切换、明细打开后检查绑定，继续编辑文案并刷新验证；初次绑定数不能代替操作后可编辑性。每个业务页面分别提供对应功能说明。

- 每个目录项必须指向独立data-review-panel页；逐项点击，仅对应页可见且回到顶部。刷新恢复该页。禁止用同一页内部标题锚点替代页面切换。

- 演示中每个业务页有自己的左侧目录项，不在产品外另设切换按钮；图表必须置于白底卡片，核对圆角、间距、边框、标题与当前页面说明，而不只检查SVG数量。

- PRD 含 Mermaid 时执行 `validate-review.mjs 原型.html --prd PRD.md`，逐张对照源图检查节点、参与方、分支、箭头和回路；指纹检查不等同图形正确。时序、流程和状态图在真实浏览器及导出文件逐张检查，不能只验收产品页面。

- 功能结构的整张图使用白底卡片；目录及页标题为「功能结构」，在图内能力节点标新增／改动／复用。Mermaid 流程与时序使用公共浅蓝主题，逐图核对节点、连线、文字与备注的配色。

- 交付前运行 scripts/verify.mjs，核对验收记录中 HTML/PRD 指纹对应最终文件；逐页目检截图并记录实际业务交互的验证结果。结构脚本不判断图片是否忠实、文案是否正确、置顶规则是否符合业务，必须通过实际场景验证。
