# 验收范围

## 最终文件的自动检查

- 运行 `scripts/verify.mjs`，确认验收记录的 HTML 和 PRD 指纹对应最终文件。脚本核对评审组件、独立目录与导航、代表性操作后的文案绑定、1440/1920 整页溢出、画板裁切及编辑与导出，并保存逐页截图。
- PRD 有 Mermaid 时核对源指纹和 SVG 数量。图源、导出文案与重开脚本检查通过后，继续核对实际呈现和业务结果。

## 浏览器走查

- **依据与同步**。按本次改动映射核对端、主体、入口、权限、保存与生效边界。修改后回看受影响的 PRD 正文、线框、静态画板及演示。静态画板固定样例、连线触发条件和实际演示一致。
- **画板与现状**。检查首屏、实际长页、弹窗或抽屉、关键改动以及相邻的原有控件。手机内框按目标设备检查。截图叠层下的原入口、菜单和文字仍应可读、可操作。逐张对照源图检查参与方、节点、分支、回路和配色。
- **导航与文案**。走查三个板块、固定顶栏、左侧独立目录、刷新恢复及无效锚点回退。首次打开及点击「需求概述」默认显示第一项「需求说明」，正文只呈现源自 PRD 的「需求背景」和已确认的「功能说明」。待确认项留在 PRD。各业务页从左侧进入，多个流程图在「业务流程」内切换。对照 `prd-rules.md` 检查用户操作文案及动态反馈，保留必要的业务提示。
- **业务结果**。在本次关键路径上实际输入、点击和确认。对照 PRD 核验列表、状态、权限与反馈。有取消、拒绝或失败时验证草稿、已保存状态及恢复路径。跨端联动按实际角色和状态验证。记录每条已走路径的预期与实际结果。
- **导出重开**。实际导出并在干净的浏览器上下文打开，复跑最关键的操作链。确认画板、图示、编辑文案与必要配置仍可用，检查无重复画板、意外业务重置或编辑工具残留。

首次交付走查三个板块及关键路径。迭代集中复验受影响页面、设备和业务结果，最终自动检查仍以当前文件为准。已查范围和剩余项写入交付说明。
