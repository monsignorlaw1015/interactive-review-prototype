# 静态画板与演示共用界面

优先使用一个页面组件/渲染函数接收状态：`renderPage({mode, data, errors, overlay})`。静态板块传固定场景，演示传当前草稿/已保存状态；两者共用页面结构与文案定义。场景名按本次PRD定义，不硬编码任何业务类型。

若使用DOM复制：

1. 原始业务组件先完成编辑键绑定，再复制固定场景。自动编辑器初始化后复制可继承已生成的键；提前复制时由项目渲染器显式生成稳定键。
2. 从原组件复制产品视口，不复制外层section或功能面板。给静态视口使用单独类名，如`.review-static-viewport`，避免复制`.prototype-viewport/.macos-window/.mobile-frame`后被业务初始化和文案门禁误识别为第二套演示页面。样式通过共用内部组件或别名复用，不靠复制事件。
3. 删除/重新命名所有重复ID和label关联，隔离radio的name；业务脚本只查询演示区域。静态画板正常模式不可执行保存、下单等操作。
4. 复制后应用固定场景：输入值、checked、错误提示、弹层开闭等。静态场景值独立于可保存的业务状态，文案键只共享相同含义的内容。
5. 静态尺寸容器匹配缩放后的宽高；按需加长长页，而不是用固定截图高度裁切。变化标注需在静态视口也可见。
6. 导出时保留静态DOM；初始化先检查画板是否已存在。重新打开导出文件不得再追加一遍，也不能重新渲染覆盖用户编辑的文案。
7. 在浏览器验证“修改演示文案 → 静态同步 → 刷新 → 导出 → 新上下文打开”，并独立验证固定场景不随演示操作漂移。

画板组、页面数、分支数由PRD决定。单页没有跳转就不加箭头；多分支按实际操作连线，超宽组横向滚动。不要为了适配一个示例规定每组两页或固定六张画板。
