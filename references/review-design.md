# 评审外壳设计基准

已认可的商品购买范围交互测试版是评审外壳的视觉参照；业务界面仍按各项目现状还原。不能仅复制三块名称，重新发明切换方式和卡片外观。

- 顶栏64px，白底、固定顶部；三大板块用同一套分段按钮。
- 外层灰底；左右24px留白；目录206px，间距24px，主区自适应。
- 左侧目录为白色卡片，圆角24px、浅边框/阴影；项目项使用胶囊高亮。目录名称与独立页标题一致。
- 演示页以“产品视口 + 当前页面说明”横排，说明栏约300px；说明卡片白底圆角24px，四类正式栏目不改变。实际可用视口缩小时先适配业务区域，不添加两层横向滚动。
- 流程、时序、状态图均放入 `.review-diagram-card` 或 `.review-flow`：白底、24px内边距、12px圆角、浅边框/阴影。SVG保持自然尺寸，图超宽在卡片内滚动，不铺满放大、不直接贴灰底。`ReviewComponents.flow`默认带该卡片。
- 静态画板按既定分组、连线与缩放组件展示，说明与变化红框保留。

业务页面只有一套评审导航：左侧目录。跨业务端、跨业务页面都注册为各自demo页面，不在内容上方另造一排“商家端／内部平台”等按钮。真实产品已有的账户页签、筛选切换和弹窗操作保留在产品视口内；它们不等同于评审页面导航。共用渲染器可以按页面事件渲染或移动共享视口，但标题、说明、目录高亮必须对应当前已注册页面，不允许空白占位或重复ID。

验收时至少核对：目录位置与独立页、图表白底容器、卡片圆角/内边距、标题层级、说明栏、原尺寸缩放和视口溢出。不能只检查存在SVG和三个板块。

功能结构、业务流程、关键时序统一使用白底图卡。功能结构目录及页标题统一为「功能结构」；「新增／改动／复用」标在图内对应能力上，不放进目录名。功能结构使用 `ReviewComponents.features`（自动添加白底容器），分支用 `change` 显示变更标记。

所有新渲染 Mermaid 使用 `assets/diagram-theme.json` 的公共主题：节点浅蓝 `#f6f9ff`、节点边框 `#7da9e9`、连线 `#7188aa`、文字 `#303741`，时序参与方及备注也沿用同一色系。不要回退默认紫色主题或逐项目另配颜色。源图结构保持不变，只统一表现。
