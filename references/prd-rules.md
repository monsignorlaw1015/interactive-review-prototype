# 功能概览写法规范

> **适用范围**：设备无关。PC · macOS / Mobile 系列共用同一套 PRD 写法。

每个 section 的功能概览是给评审者的页面级说明，不是页面视觉标注的清单。统一按「功能说明」「逻辑说明」「交互说明」「备注」组织。只优化正文表达，保留专业术语、业务名称、字段名称和状态名称。

## 栏目与表达（MANDATORY）

按「功能说明 → 逻辑说明 → 交互说明 → 备注」呈现，无适用内容时省略，不填空栏目。同一事实只写一次，规则及反馈可用完整句子关联，不为凑栏目拆散或重复。保持简洁、完整的书面语；因果链用于检查信息是否完整，不要求正文使用箭头或固定句式。

### 1. 功能说明

用一句话说明入口和本页目的。不要解释评审者一眼能看出的标题、容器、边框、普通按钮和既有外壳。

### 2. 逻辑说明

描述判断条件、权限、适用范围、数据和状态变化，以及已确定的异常规则。

例如：修改解析方式后保存，文件重新解析，状态先变为「解析中」；完成后为「已就绪」，失败后为「解析失败」。仅修改文件名称时不重新解析，解析状态保持不变。

### 3. 交互说明

- 多个字段确实需要比较默认值、必填性、来源或限制时，优先用字段表，放在「功能说明」。简单选择和少量操作直接用文字，不以数量强制制表。单个字段的选项和按钮不计为多个字段。
- 原型右栏宽度有限，可删去重复列或改用字段条目，不能为凑表格挤成难读的长列。
- 少量关键操作用「动作 → 结果」短句，不强制加粗元素名。
- 不逐项复述普通控件和装饰；颜色本身承载状态或告警时才写。允许准确且必要地使用「展示」「触发」等词，不设禁词。

示例：

| 字段名称 | 控件类型 | 默认值/占位符 | 说明 |
|---|---|---|---|
| 文件名称 | 文本 | 回填当前文件名 | 可修改；去掉首尾空格后不能为空。 |
| 目标知识库 | 下拉 | 当前所属知识库 | 可切换；保存后文件移动到所选知识库。 |

#### 操作与反馈示例

围绕「用户动作 → 必要处理 → 用户可见结果」写完整结果，尤其不能遗漏归属、状态、列表、通知或后续任务变化。

> 点击「保存」：五项均已填写时保存并关闭弹窗，刷新知识列表后提示「已保存」。解析方式或解析完成后有改动时，文件先进入「解析中」；完成后更新为「已就绪」。

### 4. 备注

备注承接待确认项、演示限制及补充信息。已确定的异常规则归「逻辑说明」，错误提示、弹窗保留及恢复方式归「交互说明」。没有依据时不要编造。

> 推送展示期限仍待产品确认；本页 8 秒仅为弹窗关闭倒计时示意，不代表推送展示期限。

### 条件分支型描述

同一控件在不同上下文有不同行为时，用**条件对照**清晰列出每种分支，避免歧义。

示例：

> - 默认渠道不可删除；删除入口禁用，提示「默认渠道不可删除」。
> - 非默认渠道允许删除，具体确认及删除结果以 PRD 为准。

写法要点：条件前缀简短；每个会导致不同可见结果的分支独立写；不为无业务意义的颜色、光标或 hover 效果单列说明。

## 重复内容处理

同一模块内多个 section 共享相同结构时，只在**第一个 section 完整描述**，后续 section 改用引用，降低维护成本。

### 四类常见重复场景

| 场景 | 示例 | 引用写法 |
|------|------|---------|
| **外壳级通用模块**（顶部窗口栏 / 侧边栏 / 顶部工具栏）在同模块所有 section 重复出现 | 页面-01 / 页面-02 / 页面-03（同 app-shell 套同一套外壳） | 第一个 section 完整描述这些通用模块；**后续 section 一律省略，不写「与首页保持一致」之类废话引用**，只列主区差异；除非外壳本身有差异（如某 tab 隐藏侧栏某项）才单独写一行差异说明 |
| **详情页多状态变体**（同模板、不同主按钮/badge） | 详情页-01 / 详情页-02 / 详情页-03（不同状态） | `详情页通用结构（返回链接、图标 + 名称 + 副标题、完整简介、操作按钮）同 详情页-01` |
| **弹窗通用结构**（遮罩 + X 关闭按钮）在同模块多处弹窗 | 弹窗-01 / 弹窗-02（不同弹窗） | `遮罩、X 关闭按钮同 弹窗-01；底层为 页面-01 dimmed 态` |
| **遮罩在同文件连续出现**（抽屉/弹窗叠加） | 弹窗-02 → 弹窗-03 | `遮罩同上；[本节独有内容]` |

> **外壳级模块的特殊性**：与详情页 / 弹窗 / 遮罩三类「内容级」重复不同，外壳（顶部窗口栏 / 侧边栏 / 顶部工具栏）是**整个应用共用**的，写 1 次足够。后续 section 写「侧边栏与首页一致」这种引用句本身就是赘述——直接删，**留白即默认外壳无变化**。只有当外壳真的变了（如某侧栏列表保留上次缓存这种差异），才独立写一条 bullet 说差异。

### 引用规则

1. 第一个引入该结构的 section 必须完整描述，它是后续 section 的锚点
2. 后续 section 先写一行引用，再列差异点（用「差异：」或直接列差异 bullets）
3. 差异内容仍按正常描述模板写，不省略
4. 若两个弹窗内容差异较大，不强制引用，完整描述更清晰

### 正面案例

「编辑」/「编辑-默认」/「删除」三个 section 的引用式差异描述典范：

- 「编辑」完整描述编辑子页结构
- 「编辑-默认」首行 `结构与「编辑」一致，差异点见下`，之后只列差异（默认项额外的 badge、只读字段、恢复按钮等）
- 「删除」首行 `底层背景为「编辑」子页内容...`，复用底层描述，重点写弹窗本身

## 改动型原型：功能概览只写本次改动

当原型是给**既有页面**新增 / 修改功能的迭代切片（而非全新页面）时，功能概览**只描述本次改动引入或改变的元素**，既有功能一律不复述。

- ❌ 反例：给某详情页新增一个配置区，却把返回入口、状态徽标、主操作按钮、依赖列表、删除区等既有元素全列一遍 —— 冗余
- ✅ 正例：只写新增的配置区及其中的开关 / 入口卡片；既有头部、列表、操作区一概不写
- **判断标准**：这条 bullet 描述的元素，是本次改动**新增或改变**的吗？不是 → 删
- 全新页面说明用途、字段及关键操作，也不枚举装饰和通用外壳。
- section 标题可点明改动主题（如「XX 页 · 新增 XX 区」），让读者一眼知道本切片只讲增量

## PRD 写作风格（人类视角，不写代码语言）

PRD 旁注的读者是 **产品 / 测试 / 研发**——三类都是人。写法要保证 3 个角色都能 0 上下文读懂：

### 1. 用产品语言，禁止代码语言

| ❌ 反例 | ✅ 正例 |
|---|---|
| `sidebar-brand 用 .brand-mark + h2.brand-name 渲染` | 左侧导航栏品牌区：顶部展示品牌 logo + 文字 |
| `AgentStatusBadge variant=success` | 卡片右上角展示绿色「已安装」徽标 |
| `onClick → router.push('/detail/:id')` | 点击后前往对应详情页 |
| `installedCount > 0 ? showBadge : null` | 当任一数字为 0 时该项徽标自动隐藏，让顶栏保持简洁 |

### 2. 系统级元素描述要平台无关

涉及操作系统、浏览器、设备等会变的元素，描述用「跟随...呈现」「按...而定」「原型图仅展示 X 风格作示意」，不要写死具体形态：

- ❌ 「窗口栏左上展示红黄绿三个圆点（关闭/最小化/最大化）」
- ✅ 「窗口边框跟随用户当前操作系统呈现，原型图仅展示 macOS 风格作示意」

### 3. 品牌/视觉细节不写括号注释

正式 logo 待定时不要在 PRD 写「（紫色方形 logo + 文字）」之类装饰描述。原型用什么视觉是另一回事，PRD 描述的是「有 logo + 有文字」这件事本身。

### 4. 关键交互独立成 bullet

不要把交互塞在状态描述末尾，分行写明确：

- ✅「点击「进入」，打开该卡片对应的详情页。」

### 5. 失败 / 异常处理独立成 bullet

不要让失败处理塞在「状态流转」末尾。toast 文案、列表保留逻辑、错误后的可恢复路径**单独一条 bullet**：

- ✅「**安装失败处理**：安装失败时弹出 toast 提示「{对象名称} 安装失败，请重试」；任务队列保留该失败任务记录，用户可在任务队列中查看错误详情或重新触发安装」

### 6. 不写「整体视觉」「整体氛围」这类废话 bullet

「浅灰桌面背景 + 圆角窗口 + 投影」属于原型视觉而非产品需求。删。

### 7. 版本号 / 数量等数据展示规则要枚举所有分支

数据格式因状态而异时，逐个状态列出：

- ✅「**版本号展示规则**：已安装的项显示当前已装版本（如 v1.0.45）；**可升级**的项同时展示「当前版本 → 可升级版本」（如 v0.10.0 → v0.11.0）；未安装 / 安装中 / 检测中的项显示「最新版本：vXX」」

## 输入 PRD 与 HTML 面板的关系

### 完整示例：编辑文档

以下依据用户提供的编辑文档说明，仅演示写法，不得将业务规则套到其他需求。

**功能说明**

点击知识列表或「查看文档」弹窗中的「编辑」，打开同一个「编辑文档」弹窗。以下五项均必填，回填当前值且均可修改。

| 字段名称 | 控件类型 | 默认值 | 说明 |
|---|---|---|---|
| 文件名称 | 文本 | 当前文件名 | 去掉首尾空格后不能为空。 |
| 目标知识库 | 下拉 | 当前所属知识库 | 可选当前企业的知识库。 |
| 文档分类 | 下拉 | 当前分类 | 选项及顺序取自「文件分类管理」。 |
| 解析方式 | 下拉 | 当前解析方式 | 自动分段（推荐）、按页切分、按固定字数切分。 |
| 解析完成后 | 下拉 | 当前设置 | 立即建立检索索引、暂不索引。 |

**逻辑说明**

修改目标知识库后保存，文件移到所选知识库；原知识库文件数减 1，所选知识库文件数加 1，列表的「知识库」标签同步更新。

解析方式或解析完成后设置有改动时，保存后重新解析，状态先变为「解析中」；完成后为「已就绪」，失败后为「解析失败」，可在知识列表重新解析。仅修改文件名称、目标知识库或文档分类时，不重新解析，解析状态保持不变。

**交互说明**

点击「保存」，校验通过后关闭弹窗，刷新知识列表并提示「已保存」。有必填项为空时，在对应字段下提示，弹窗保持打开且不保存；文件名称为空时提示「请输入文件名称」。点击「取消」关闭弹窗，不保存本次修改。

本例没有额外待确认项或演示限制，省略「备注」。窄面板中可将字段表改为逐字段条目，保留同样的业务信息。

输入的 PRD Markdown 是业务事实来源。HTML `prd-panel` 是其页面级摘要，不新建或反写一份 PRD。逻辑、状态和边界均只能提取自输入 PRD；信息不足时在原型中标「待 PRD 明确」，不要自行补规则。

HTML 面板结构（按页面事实删减不适用分组）：

```html
<div class="prd-section">
  <div class="prd-section__title">功能说明</div>
  <p>{入口与目的}</p>
</div>
```

每个页面 section 对应一个 `prd-panel`，其中按需包含多个 `prd-section`，只描述当前页面。栏目顺序如下：

```html
<div class="prd-section"><div class="prd-section__title">功能说明</div><p>...</p></div>
<div class="prd-section"><div class="prd-section__title">逻辑说明</div><ul>...</ul></div>
<div class="prd-section"><div class="prd-section__title">交互说明</div><ul>...</ul></div>
<div class="prd-section"><div class="prd-section__title">备注</div><ul>...</ul></div>
```
